# Swarm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `swarm` CLI, tmux hooks, an iTerm helper and an orchestrator skill to the agent-tmux plugin. Together they open projects as tabs in the user's hotkey iTerm window, start lieutenants in their own tabs (shell | lieutenant / worker), keep those layouts and labels in place while Claude Code adds teammate panes, and let the orchestrator quietly nudge stuck lieutenants.

**Architecture:** `bin/swarm` is a thin bash 3.2 dispatcher. It sources focused libraries from `lib/swarm/`. All tmux access goes through one wrapper, so tests can run against a private tmux server. iTerm-specific work (finding the hotkey window, moving one tab, opening a window) is done by `bin/swarm-iterm.py`, which uses the `iterm2` Python API. The bash side treats that helper as optional. Global tmux hooks call `swarm _retile-session`, which acts only on windows tagged by swarm. (The spec's `bin/swarm-place-tab.py` is named `bin/swarm-iterm.py` here, because it also handles hotkey detection and `--own-window`. Placing a tab is called through `swarm_iterm place-tab`, not a `swarm _place-tab` subcommand.)

**Tech Stack:** bash 3.2 (macOS `/bin/bash`), tmux 3.8, jq, Python 3 with `iterm2` (optional, in `~/.agent-tmux/venv`), Claude Code CLI 2.1.311.

**Spec:** `docs/superpowers/specs/2026-10-28-swarm-design.md`. Read it before any task. Fact numbers below refer to it.

## Global Constraints

- Scripts start with `#!/usr/bin/env bash` and must run on **bash 3.2**: no `declare -A`, `mapfile`, `${x,,}`, `local -n`, `|&`, or `;&`.
- Every entry point prepends `/opt/homebrew/bin:/usr/local/bin` to `PATH` (fact 17).
- All tmux calls go through `tmx`, which runs `tmux -L "$SWARM_TMUX_SOCKET"` when that variable is set and plain `tmux` otherwise.
- Address tmux objects by `@window` / `%pane` ids or session names, never by window index or `session:name` (facts 6, 16).
- Never run `move-window` or `swap-window` (fact 19).
- Never touch windows without a `@swarm-role` tag: no layout, rename, kill or move (anti-goal).
- No code path opens an iTerm window except `open --own-window`.
- Swarm never creates worktrees or branches, and never edits `~/.claude.json` or `~/.claude/teams/`.
- Session names: `<project>-main` and `<project>-<lt>`. Tab names: `<project>-main` and `<project>:<lt>`. `main` isn't a valid lieutenant name.
- Window tags: `@swarm-project`, `@swarm-role` (`main` or `lieutenant`), `@swarm-name`, `@swarm-dir`, `@swarm-report`, `@swarm-layout` (`stack` or `grid`), `@swarm-session-id`, `@swarm-telegram`. Pane labels go in the pane option `@name`.
- Config file: `${SWARM_CONFIG:-$HOME/.agent-tmux/swarm.conf}`. State: `${SWARM_STATE_DIR:-$HOME/.agent-tmux/swarm}`.
- Setting defaults: `session auto`, `lt_model opus`, `stall_min 20`, `idle_min 2`, `poll_sec 15`, `retile_delay 0.6`, `telegram_project` (empty), `telegram_plugin telegram@claude-plugins-official`, and roots default to `~/workspace`.
- Watch output lines exactly: `stalled <lt> <minutes>`, `idle-unreported <lt>`, `over-cap <lt> <n>`.
- Helper caps: 1 for `stack`, 3 for `grid`.
- `tests/codex-review.test.sh` must keep passing, and `tmux-bridge`, `smux` and `codex-review` must not change behavior.

## Review Focus

1. **Odd project names and paths** (a directory `~/workspace/my.proj` or a path with a space): tmux treats `.` and `:` specially in targets, so names are sanitized to `[A-Za-z0-9_-]` (anything else becomes `-`), and paths with spaces work. Tested in Tasks 2 and 6.
2. **Agent-only commands run in the wrong place** (`delegate`, `report`, `layout` from a plain terminal or a non-swarm pane): a clear error, non-zero exit, and nothing changes. Tested in Tasks 5, 7 and 8.
3. **Hooks firing in the user's own windows** (a split in session `0`'s untagged tabs): `_retile-session` returns immediately without sleeping and leaves the layout byte-for-byte unchanged. Tested in Task 5.
4. **`claude agents --json` failing or printing non-JSON** (an older CLI, nothing running): `status` shows `unknown`, `watch` prints nothing and keeps running, and `open` treats the orchestrator as not running. Tested in Tasks 8 and 9.
5. **Repeats** (`open` on an already-open project whose orchestrator is alive, or `delegate` with a name already in use in that project): no duplicate tab. `open` just selects the tab; `delegate` fails, naming the existing tab. Tested in Tasks 6 and 7.

### Task 1: CLI skeleton, common helpers, config parsing, `swarm config`

**Files:**
- Create: `bin/swarm`, `lib/swarm/common.sh`, `lib/swarm/config.sh`, `tests/swarm-lib.sh`, `tests/swarm-config.test.sh`

**Interfaces:**
- Produces (`common.sh`):
  - `swarm_die <msg>`: prints `swarm: error: <msg>` to stderr and exits 1.
  - `swarm_warn <msg>`: prints `swarm: warning: <msg>` to stderr.
  - `tmx <args...>`: runs tmux as described in Global Constraints.
  - `swarm_state_dir`: echoes the state dir, creating it if needed.
  - `swarm_wopt <@win> <key>`: echoes the window option's value, or an empty string.
  - `swarm_windows <session> [key value]`: prints the `@id`s of windows in `session` (all of them, or only those where option `key` equals `value`), in tmux index order, one per line.
  - `swarm_caller_window`: echoes the `@id` of `$TMUX_PANE`'s window. If `$TMUX_PANE` is unset or unknown, dies with `not inside a tmux pane`.
  - `swarm_sanitize <name>`: replaces each character outside `[A-Za-z0-9_-]` with `-`.
  - `SWARM_ROOT`: the repo directory.
- Produces (`config.sh`):
  - `cfg_load`: reads the config file. A missing file is fine (all defaults). Sets the globals `CFG_ROOTS` (newline-separated, `~` expanded), `CFG_PROJECTS` (`name<TAB>path` lines), `CFG_GROUPS` (`name<TAB>member member…` lines), `CFG_SETTINGS` (`key<TAB>value` lines) and `CFG_ERRORS` (`line N: <problem>` lines).
  - `cfg_get <key>`: echoes the setting, or its default.
  - `cmd_config`: prints the parsed config and the errors. Exits 1 if there are errors.
- Produces (`bin/swarm`): `SWARM_SUBCOMMANDS="open delegate status peek report close watch layout config help _retile-session _resolve _home"` (names starting with `_` are hidden from usage and are internal or test hooks`. It dispatches `swarm <sub> args` to `cmd_<sub with - → _>` (so `_retile-session` → `cmd__retile_session`). With no arguments it prints usage and exits 1.
- Produces (`tests/swarm-lib.sh`):
  - `t_setup`: makes a temp `WORK`; exports `SWARM_TMUX_SOCKET=swarm-test-$$`, `SWARM_CONFIG=$WORK/swarm.conf`, `SWARM_STATE_DIR=$WORK/state` and `HOME=$WORK/home`; puts `$WORK/bin` and the repo `bin/` first on `PATH`; installs the fakes; registers cleanup that kills the private server and removes `WORK`.
  - `t_tmux <args>`: tmux against the private server.
  - `t_session <name> [dir]`: creates a detached 200x50 session with `default-shell /bin/sh`.
  - `expect <name> <code> <substring> <cmd...>`, `expect_eq <name> <want> <got>`: as in `codex-review.test.sh`.
  - `t_done`: prints the summary; exits 1 if anything failed.
  - Fake `claude` in `$WORK/bin`: `claude agents --json` prints `$FAKE_AGENTS_JSON` (a file; default `[]`), and exits 1 if `FAKE_AGENTS_FAIL=1`. Any other invocation appends its args, one line, `\x1f`-separated, to `$FAKE_CLAUDE_LOG`, then loops on `sleep 60` (no `exec`, so `ps` still shows the args).
  - Fake iTerm helper `$WORK/bin/fake-iterm`: appends its args to `$FAKE_ITERM_LOG`, prints `$FAKE_ITERM_OUT` if set, and exits with `${FAKE_ITERM_CODE:-0}`. Exported as `SWARM_ITERM_HELPER`.

### Task 2: Argument resolution

**Files:**
- Modify: `lib/swarm/config.sh`
- Test: `tests/swarm-resolve.test.sh`

**Interfaces:**
- Consumes: `cfg_load`, `swarm_sanitize`.
- Produces: `cfg_resolve <arg>...`. On success it prints one `name<TAB>absolute-dir` line per project, in order, with duplicates (same dir) dropped after their first appearance, and exits 0. On any failure it prints nothing to stdout, prints `swarm: error: …` to stderr and exits 1.

  - Two different dirs with the same name fail with `name 'x' is used by both <d1> and <d2>; add a project line`.

### Task 3: iTerm helper

**Files:**
- Create: `bin/swarm-iterm.py`, `lib/swarm/iterm.sh`
- Test: `tests/swarm-iterm.test.sh`

**Interfaces:**
- Produces (`bin/swarm-iterm.py`, run as `python -I swarm-iterm.py <cmd>`):
  - `plan-order --tabs 27,28,29,30 --new 30 --project 27,28`: pure, with no `iterm2` import. Prints the new comma-separated order: the current order with the `--new` tab removed and inserted right after the last tab that's in `--project`. If no `--project` tab is present, the order is unchanged.
  - `place-tab --new @30 --project @27,@28`: finds the terminal window that contains a tab with `tmux_window_id == "30"`, computes its order with the same function, and calls `window.async_set_tabs` once, and only if the order changed.

### Task 5: Layouts, labels, hooks, `swarm layout`

**Files:**
- Create: `lib/swarm/layout.sh`
- Modify: `config/tmux.conf`
- Test: `tests/swarm-layout.test.sh`

**Interfaces:**
- Consumes: `tmx`, `swarm_wopt`, `swarm_windows`, `cfg_get retile_delay`, `swarm_caller_window`.
- Produces:
  - `swarm_retile_window <@win>`: applies the layout from `@swarm-layout` (default `stack`), then labels helpers.
  - `cmd__retile_session <session> [--now]`: returns at once if the session has no window with `@swarm-role` (`main` or `lieutenant`). Otherwise it sleeps `retile_delay` (skipped with `--now`) and retiles each tagged window.
  - `cmd_layout <stack|grid>`: must be run from a lieutenant's pane (the caller's window has `@swarm-role=lieutenant`), otherwise it dies with `swarm layout must be run from a lieutenant's pane`. It sets `@swarm-layout` and retiles at once.
  - `layout_checksum <string>`: echoes the 4-hex-digit tmux checksum.
- The panes in a tagged window, by pane index: 0 = shell, 1 = agent (orchestrator or lieutenant), 2+ = helpers.
- `stack`: `set -w main-pane-width 50%`, then `select-layout main-vertical`.
- `grid`: a computed layout string. With window size `W`x`H`, the shell column is `S=(W-1)/3` wide and the right column `R=W-1-S`. The right column holds `k` panes (agent plus helpers, at most 4). If `k=1`, that pane fills the column. Otherwise there are two rows: the top row is `(H-1)/2` high and the bottom row `H-1-top`. The top row gets the first `ceil(k/2)` panes and the bottom row the rest, and the widths within each row are split evenly (the remainder goes to the last pane). Any panes beyond the first 5 are left as tmux has them. The cell grammar is `WxH,X,Y,ID` for a leaf, `{…}` for a left-right split and `[…]` for a top-bottom split. Siblings are separated by 1 column or row, and the string is prefixed with `checksum,`. Checksum algorithm (tmux `layout_checksum`):

  ```bash
  csum=0; for ((i=0; i<${#s}; i++)); do printf -v c '%d' "'${s:i:1}"
    csum=$(( ((csum >> 1) + ((csum & 1) << 15) + c) & 0xffff )); done; printf '%04x' "$csum"
  ```
- Labels: for each pane with index ≥ 2, read `ps -o args= -p <pane_pid>`. If it contains `--agent-name X`, set the pane's `@name` to `X`.
- `config/tmux.conf` appends:

  ```
  set-hook -g 'after-split-window[90]' "run-shell -b '[ -x \"$HOME/.local/bin/swarm\" ] && \"$HOME/.local/bin/swarm\" _retile-session \"#{session_name}\" || true'"
  set-hook -g 'after-kill-pane[90]'    "run-shell -b '[ -x \"$HOME/.local/bin/swarm\" ] && \"$HOME/.local/bin/swarm\" _retile-session \"#{session_name}\" || true'"
  ```

  Check the quoting by running `tmux -L x -f config/tmux.conf new -d` and then `show-hooks -g`: the command must contain a literal `#{session_name}` inside double quotes (fact 25).
